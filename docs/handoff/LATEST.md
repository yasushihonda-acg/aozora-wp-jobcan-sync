### 経緯詳細

**相談員イラストカード化(PR #186)**: 前セッションからの中断点。SCENE #21で3枚生成、10項目採点+耳元拡大確認(sipsによるピンポイントクロップ)を実施。1枚(高齢の利用者様・ご家族と3人でテーブルを囲みタブレット提示するシーン)は採点の過程で既採用済み`illust-job-consultant.png`/`-2.png`(ケアマネジャー)と構図がほぼ同一(3人・テーブル囲み・タブレット提示のポーズまで酷似)と判明し不採用 — PR #183(総合職)で発見された「SCENEプロンプトに区別指示を明記していてもChatGPT UI側が構図をdriftさせる」パターンの2回目の再現。残り2枚(施設内案内の歩行シーン/窓口一対一相談シーン)をメイン+バリエーションとして採用。`selectors.yaml`に`consultation`バケット新設(`consultant`から「相談員」synonymのみ分離・移動)。

**サポート職イラストカード化(PR #188/#189)**: 残り6職種の中で件数最多(7件)のサポート職(清掃・洗濯・調理・送迎)を次の対象に選定。SCENE #23では施設長候補SCENE #20の教訓を踏まえ、ACCESSORY RULEを「NO earring, NO rings, NO dangling jewelry of any kind」と無条件で指定。それでも生成3枚のうち2枚(清掃シーン・洗濯シーン)は耳元拡大確認で小さなスタッドピアスが視認され不採用 — **無条件禁止ルールを明記していても発生しうるという新しい教訓**。洗濯シーンはさらに既存`illust-job-visit.png`(訪問介護員、洗濯物たたみ)と主要モチーフが重複しており二重の不採用理由。残り1枚(送迎車へのご案内シーン)を単独採用、`support`バケット新設(`care`から分離)。1枚プールのため清掃/調理のバリエーション追加は次セッション以降のフォローアップとして記録。

**訪問リハビリイラストカード化(PR #191/#192)**: 残り5職種で件数同率1位(6件)の訪問リハビリを選定。SCENE #24は既存`illust-job-nurse.png`(血圧測定などの医療行為)・`illust-job-visit-3.png`(手を引く歩行介助)と区別できる「機能訓練・運動療法」(リハビリバーを使った運動)を指定。生成1枚(本田様の環境で画像キャッシュが一度失効し再送いただいた)は10項目採点+耳元拡大確認とも全Pass、既存カードとも視覚的に完全に区別できたため単独採用。`visiting-rehab`バケット新設(`nurse`から分離)。

**デプロイ**: 各PRマージごとに`docker buildx build --platform linux/amd64 --push`(Web用`sync/Dockerfile`+Job用`sync/Dockerfile.job`を並行ビルド)→ Cloud Run Job(`aozora-sync-daily`)/Webサービス(`aozora-sync`)を再デプロイ→Cloud Scheduler手動トリガーで即時同期→Playwright実機確認(新カテゴリの新画像反映+隣接する既存カテゴリの回帰なし)を3職種とも実施。いずれも本番証跡あり(相談員: `category_id=18984`がconsultation系2枚のみ・`18985`/`22014`が既存のまま、サポート職: `43764`がsupport系1枚のみ・`18773`が既存のまま、訪問リハビリ: `41046`がvisiting-rehab系1枚のみ・`18983`が既存のまま)。
