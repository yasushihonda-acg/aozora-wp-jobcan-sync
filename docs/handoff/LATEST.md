## 得られた教訓（次セッション・他プロジェクトでも参照価値あり）

- **改行位置のCSS対応は万能ではない**: `word-break: keep-all` + `text-wrap: balance`は「不自然な字割れ」は防げるが、「決められた行数に収める」という要求には応えられない。文字数そのものを削る(句読点除去等)方が確実な場合がある
- **静的アセットの1時間キャッシュ**(`Cache-Control: public, max-age=3600`)は、コード修正が正しく本番デプロイされていても、既にサイトを開いたことのあるブラウザにはすぐ反映されない。`fetch(url, {cache:'no-store'})`でサーバー配信自体の正しさを切り分けてから案内すると誤解を防げる(前回セッションでも同じ教訓を得ており、今回で2回目の実践確認)
- **ローカル検証用の一時ファイル**(`mockup/_verify_scratch.html`、スクリーンショットPNG等)はgit管理下のディレクトリに書き出さざるを得ない場面(Playwright MCPのallowed rootsの制約)があるが、確認後は都度`rm`して`git status --short`でクリーンを確認する運用を徹底
